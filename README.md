# 票务占座过期与出票一致性

使用者：演出票务渠道对账员。回放多渠道占座付款出票日志，找出售卖冲突与超时悬单。

核心规则：占座租约使用事件时间，付款时刻必须早于到期点，同版本冲突拒绝，释放后旧支付不能复活席位。

## 启动

```sh
docker compose up --build -d
docker compose exec -T app pytest -q
docker compose config --quiet
```

浏览器访问 http://localhost:18204 。首页已装载脏样例，可编辑CSV与参数后运行，也可上传文件。八个导航分别对应业务步骤。`sample_data/group.csv` 为团购多座订单补位样例，含部分出票、票号缺失与到期点付款受阻。

## 模块

- M1 渠道接收：接收各渠道事件，入口 `/m/1`、`GET/POST /api/m1`。
- M2 座席映射：映射座席并裁决版本，入口 `/m/2`、`GET/POST /api/m2`。
- M3 租约回放：回放占座释放租约，入口 `/m/3`、`GET/POST /api/m3`。
- M4 支付归属：按有效租约归属支付，入口 `/m/4`、`GET/POST /api/m4`。
- M5 出票核验：检查支付及票号一致，入口 `/m/5`、`GET/POST /api/m5`。
- M6 渠道对账：核对渠道金额与悬单，入口 `/m/6`、`GET/POST /api/m6`。
- M7 补传复核：补传回放和版本复核，入口 `/m/7`、`GET/POST /api/m7`。
- M8 团购补位：同一订单记录补位结果，入口 `/m/8`、`GET/POST /api/m8`，动作 `POST /api/backfill/<run_id>`，核对导出 `GET /api/backfill.csv`。

## 团购补位一致性

团购订单一次占多个座位，渠道部分出票后，后续座位可能因租约到期出票失败。M8 按同一订单聚合应出票座位、原渠道票与补位票：

1. 已发出的原票保留渠道回执，失败事件继续留在隔离区并带行号与原因码。
2. 订单只有在全部应出票座位都有凭证（原票或补位）时才显示“已完成”，部分出票显示“部分出票”。
3. 补位只补偿有有效支付且缺票的座位；支付过期或无支付的座位列入受阻，不静默换票。
4. 补位动作带批次版本号，乐观锁冲突返回409并保留旧版状态；成功才推进版本，重跑缺失已补齐时不重复出票、不推进版本。
5. 自动分配只取既未出票、也无有效租约、且不属于受阻订单的空闲座席；也可显式指定座席，占用中或已出票会被拒绝。
6. 页面与 `/api/backfill.csv` 同时列出原票、补位凭证（旧座席→补位座席、票号、依据）与订单完成状态。

## 演示与复核

1. 运行默认样例，核查隔离原因与业务合计。
2. 修改CSV单元格或参数并重跑，保留行号与输入摘要。
3. 在 M7 复核，旧版本提交返回409；在 M8 对团购缺票座位执行补位，陈旧版本同样409且保留旧版状态。
4. 证据CSV包含采信行和隔离行，补位CSV同时核对原票、补位凭证与订单完成状态，重跑相同内容复用批次。

## 数据与目录

`app/modules/` 按业务切分；`sample_data/` 为UTF-8 BOM、GB18030及干净/脏样例；`tests/` 含规则与端到端测试。SQLite保存运行与复核，命名卷records保留重启后的记录。若需从头开始，可先停止服务并在确认不再需要记录后删除该项目records卷。

## 定义与边界

单场演出16个座席，不处理退票退款。占座租约释放或到期后，迟到付款不能恢复租约；出票必须已有有效付款且座席不可重复出票。

团购补位不改变原票与原始事件：补位凭证单独记录在批次的 `backfills` 集合，票号以 `BF` 开头且全场唯一，按订单记录旧座席、补位座席、渠道、金额与失败依据。主动释放的租约不计入订单应出票范围；无有效支付的缺失座位为受阻座位，待支付证据补齐后才可在下一次补位中处理。

详细字段、计算定义与原因码见 `docs/DATA-DICTIONARY.md`，回归证据见 `docs/DEPTH.md`。
